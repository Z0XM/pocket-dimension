# Decision Log — rhymes PRD

## Confirmed decisions
- Use BMAD artifacts as the canonical planning layer for this revamp.
- Keep the product reader-first with an always-available reading surface.
- Content types in scope: poem, article, song, diary.
- Ratings must support creators and other logged-in users.
- Editing must support plain text, Markdown, and HTML.
- Titles must support rich styling and optional title art.
- Page breaks are in scope now.
- Quick composer saves drafts by default on `Enter`, with a separate publish action.
- Drafts are never public.
- Published content is public by default and can be hidden.
- Any logged-in user can rate content.
- Default reading mode is chosen per content piece rather than by content type.
- Creator chooses how title text/title art are displayed; title art takes precedence and text title is the fallback.
- Repeating background page images are deferred for a later phase.

## Provisional decisions
- Prefer a database-backed content model over markdown files as the long-term source of truth.
- Prefer rhymes-specific roles/memberships over global-only auth roles.
- Prefer a SvelteKit migration path if implementation scope justifies it.

## Follow-up notes
- No blocking product questions remain from the current discovery set.
