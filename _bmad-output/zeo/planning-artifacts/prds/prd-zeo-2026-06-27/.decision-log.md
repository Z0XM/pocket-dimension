# zeo PRD — Decision Log

## 2026-06-27 — Initial planning session

| # | Decision | Rationale |
|---|----------|-----------|
| D1 | App name: **zeo** | User-specified monorepo project name |
| D2 | Media stack: **LiveKit Server** (self-hosted) | Recommended after feasibility analysis; SFU required for 6-person groups |
| D3 | Frontend: **SvelteKit** in `apps/zeo` | Matches monorepo conventions (watchlist, chhan-chhan, etc.) |
| D4 | Auth: **shared Better Auth** via `@pocket-dimension/auth` | Consistent with auth-backed apps in monorepo |
| D5 | Hosting: **Hostinger KVM 2** (2 vCPU, 8 GB RAM, 8 TB bandwidth) | User's existing VPS |
| D6 | Capacity: **max 2 concurrent rooms**, **max 6 participants per room** | User-specified; matches hardware envelope |
| D7 | Screen sharing: **one active sharer at a time** | Reduces CPU/bandwidth contention on small VPS |
| D8 | Default video quality cap: **720p max, 480p preferred at 5–6 participants** | Protects KVM 2 CPU headroom |
| D9 | Guest join without account: **deferred to Phase 2** | Reduces MVP auth complexity; logged-in users only initially |
| D10 | Room creation: **any authenticated user** for MVP | Can tighten to role-based in Phase 3 admin |
| D11 | Dev port: **3008** | Next available port in monorepo sequence |
| D12 | DB schema: **`zeo`** named schema in PostgreSQL | Follows monorepo pattern (watchlist, chhanchhan, etc.) |
